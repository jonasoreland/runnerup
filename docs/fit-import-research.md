# FIT Workout import research

Garmin's [Workout file description](https://developer.garmin.com/fit/file-types/workout) identifies File ID, Workout and Workout Step messages as the required structure. A FIT Activity file represents a completed recording and must not enter the workout importer.

The official [FIT Java SDK](https://github.com/garmin/fit-java-sdk) is maintained and available on Maven Central, but its [FIT Protocol License](https://github.com/garmin/fit-java-sdk/blob/main/LICENSE.txt) restricts redistribution and placing the SDK under a license that requires source distribution or modification rights. Relven is GPLv3. **Do not add the Garmin SDK dependency without a verified compatible grant.** Its public GitHub availability alone is not a compatible license.

An original bounded decoder now reads the published FIT record structure and maps executable running workouts into RunnerUp's `Workout` model. It validates the header, both CRCs, File ID type, Workout metadata, step indexes and counts. Files are limited to 1 MiB and 4,096 records; unrecognized message payloads are skipped without per-record maps. Open/manual steps can omit the duration value. The phone's workout picker accepts `.fit` files and saves a converted native workout after confirmation. A deterministic binary fixture is generated by `tools/build_fit_workout_fixture.py`; the checked-in fixture was also decoded independently with the BSD-licensed `github.com/muktihari/fit` Go decoder. That Go library is a development verifier, not an Android dependency. The Garmin SDK is not linked or redistributed.

Supported step durations are time, distance and open/manual. Supported targets are open, absolute speed ranges and absolute heart-rate ranges. Recovery, warm-up, cooldown and simple completed-step repeats retain their meaning. Activity FIT files, non-running sports, profile-relative heart-rate targets, zones without local boundaries, advanced repeat-until conditions, equipment and strength fields are rejected with named errors. This is a deliberately constrained subset, not general FIT support.

The import confirmation now displays ordered steps, nested repeat counts, localized durations, and target ranges before saving. A Robolectric persistence round-trip now decodes the checked-in FIT fixture, writes it with `WorkoutSerializer.writeFile`, reloads it with `WorkoutSerializer.readFile`, and verifies stored step intensities, durations, and targets. Remaining: test additional FIT Workout files from real devices, verify picker → save → start → finish → export on a test environment, and review FIT format edge cases. Physical-device testing remains deferred under the owner's instruction.
