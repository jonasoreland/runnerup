# Health Connect export outbox

Relven publishes only its own saved activities to Health Connect. The local RunnerUp activity database remains authoritative; this outbox is a delivery journal and never imports external records.

## Delivery and ownership

- Each local activity is identified as `activity-<database id>` and each Health Connect record type receives a deterministic `clientRecordId` under the `relven-` prefix. If deletion arrives while an upsert is pending, its tombstone includes the stable record kinds derivable from that pending payload, so an in-flight write is cleaned up as well.
- The private per-activity outbox stores an immutable workout snapshot, monotonically increasing update version, operation, status, retry details, and the record kinds Relven successfully wrote.
- WorkManager appends unique requests per activity with exponential backoff, keeping edits and deletes ordered behind an in-flight provider call. A per-session coroutine mutex also serializes worker execution within the app process. Repeating an update uses the same record identifiers and version, so retries are idempotent.
- Automatic completion queues an upsert only after the final activity summary and a durable activity-finalization row are committed in one database transaction. This row also prevents an activity from being restored as active after process death and retains an unqueued opt-in export request for startup reconciliation. It supports GPS-less activities without inventing route coordinates. Repeated completion callbacks use the same stable activity ID and identical outbox payload, so they retain one export version. Historical export remains an explicit action and can use the recorded-duration fallback for legacy activities without a finalization row. Editing queues an upsert only while export is opted in. Deleting a local activity queues deletion only for record kinds recorded as owned by Relven. It never deletes by time range or affects records from another app.
- If optional metric permission is missing, the available records are still written and the omitted permission is recorded. Required exercise-session permission waits for the user. Provider and transient failures remain retryable; permanent invalid payloads are marked failed.
- Health Connect absence or failure does not block local save, edit, or deletion. On Android versions below the supported Health Connect API gate, the bridge is not loaded.
- Automatic export is opt-in and stays off until the user requests the Android write-permission flow and grants exercise-session write access. Disabling it stops future upserts; deletion tombstones remain schedulable so Relven can remove only its own records.
- The Settings page reads permission grants and Relven's private outbox only. It does not call Health Connect record-read APIs. Historical export is an explicit user action; successful sessions are deduplicated by their stable activity-ID identity, while pending/failed sessions remain retryable.
- Settings reports the real outbox status, most recent update time, omitted optional metric permissions, retryable failures, and a count of eligible completed local activities. “Synkronisera väntande pass” schedules existing outbox operations; “Exportera tidigare pass” previews the eligible count before queuing each saved activity.
- Samsung Health is an independent Health Connect client. Users may need to enable its read access to exercise sessions in Health Connect or Samsung Health settings. Relven does not claim that Samsung Health will display a record merely because it was written.

## Source data and limitations

Only final saved activities with a positive recorded duration are eligible. Automatic completion additionally requires the committed finalization row and an export request recorded at completion; incomplete or failed final saves are not queued. GPS points are retained from the local recording, ordered by timestamp, and passed through the existing mapper's validation; missing distance, heart rate, speed, cadence, route, or lap values remain absent. Laps are exported only when the local lap and timestamped GPS markers provide valid bounds. Relven does not currently persist a trustworthy total elevation-gain measurement or active calories, so neither is synthesized for export. Strength workout details remain in Relven because Health Connect session records do not represent the app's full per-exercise performance log.

The outbox uses schema version 1, private app storage, a 50 MiB entry limit, fsync, and atomic file replacement. Export opt-in is off by default. Permission requesting, user-visible status, explicit historical backfill, and retry controls are owned by the centralized Settings integration.
