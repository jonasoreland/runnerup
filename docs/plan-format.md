# Offline training plan format

The import format is defined by [plan-v1.schema.json](../schemas/plan-v1.schema.json). App-created immutable revisions use [plan-v2.schema.json](../schemas/plan-v2.schema.json). Both reference [workout-v3.schema.json](../schemas/workout-v3.schema.json). The [running example](../schemas/examples/plan-running.json) and [strength/prehab example](../schemas/examples/plan-strength.json) validate against v1.

Imported packages use `format: "relven.plan"`, `schemaVersion: 1`, an IANA timezone, workout documents with stable IDs, and dated entries that reference those IDs. Dates are local calendar dates in the stated timezone. The parser checks duplicate IDs, real dates, timezone IDs, missing workout references, and conflicting rest/workout days. Running workouts remain executable by RunnerUp's running engine adapter. Strength and prehab exercise IDs, library revisions, exercise revisions, and English snapshots must match the installed no-equipment catalog. The in-app creator can author rep-range or timed strength/prehab workouts from active bodyweight exercises; guided sessions execute and record on the phone. App-managed revisions preserve imported and authored workout definitions, which cannot yet be edited in place.

Before parsing, importers enforce a 4 MiB UTF-8 input limit, a maximum JSON nesting depth of 32, and a maximum of 100,000 tokens. These bounds prevent oversized or deeply nested input from building an unbounded in-memory JSON tree.

The Plan destination provides day, week, and month calendars with selected-day details and links to saved-plan management. Users can create a named 1–16-week plan in the app, choose a start date and weekly training days, and assign running, strength, or prehab sessions. Strength and prehab authoring selects active no-equipment catalog exercises and configures repetitions or timed work, sets, and rest. The creator writes and validates the same canonical schema-v1 package used by import, saves it locally, activates it, and opens the calendar. It does not create a parallel plan format.

Plan packages can also be selected through Android's document picker, validated before a review summary, and saved only after confirmation. The preview shows the date range and a bounded list of sessions, and states that dates are one-time and saving does not activate or reschedule the plan. Saved packages remain in private app storage. Duplicate plan IDs are rejected instead of overwriting earlier files. A saved plan can be explicitly activated, switched, or cleared. Today shows the active plan's item for its local date. Renaming the active plan, rescheduling one entry, adding one workout or rest entry, and removing one entry each produce a complete `schemaVersion: 2` snapshot with `revision.rootPlanId`, a sequence number, and the previous revision ID; the imported package and earlier snapshots remain unchanged. Each revision preserves workout definitions and all unaffected plan data, and may contain only the one name or schedule operation it represents. The final schedule entry cannot be removed. Schedule edits do not infer completion or modify workout definitions or history. Multiple workouts may share a date; a rest day may not share a date with any other item. The original Relven v3 plan-package schema had an incompatible `enum: [1, 2]` and `const: 3` on `workoutSchemaVersion`; it was not copied as the new canonical plan schema.

The offline [AI Plan Kit](ai-plan-kit/README.md) packages the canonical plan v1, app-managed revision v2, workout v3, and exercise catalog v1 schemas with capability metadata, generation instructions, and running plus strength/prehab examples. AI output targets a new v1 plan; it must not invent v2 revision metadata.
