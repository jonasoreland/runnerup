# Offline training plan format

The import format is defined by [plan-v1.schema.json](../schemas/plan-v1.schema.json). App-created immutable revisions use [plan-v2.schema.json](../schemas/plan-v2.schema.json). Both reference [workout-v3.schema.json](../schemas/workout-v3.schema.json). The [running example](../schemas/examples/plan-running.json) and [strength/prehab example](../schemas/examples/plan-strength.json) validate against v1.

Imported packages use `format: "relven.plan"`, `schemaVersion: 1`, an IANA timezone, workout documents with stable IDs, and dated entries that reference those IDs. Dates are local calendar dates in the stated timezone. The parser checks duplicate IDs, real dates, timezone IDs, missing workout references, and conflicting rest/workout days. Running workouts remain executable by RunnerUp's running engine adapter. Strength and prehab workouts are validated read-only details; their exercise IDs, library revisions, exercise revisions, and English snapshots must match the bundled no-equipment catalog. Strength recording and execution are not supported in this phase.

Before parsing, importers enforce a 4 MiB UTF-8 input limit, a maximum JSON nesting depth of 32, and a maximum of 100,000 tokens. These bounds prevent oversized or deeply nested input from building an unbounded in-memory JSON tree.

The workout manager can select a plan package through Android's document picker, validate it before showing a review summary, and save it only after confirmation. The preview shows the date range and a bounded list of sessions, and states that dates are one-time and saving does not activate or reschedule the plan. Saved packages remain in private app storage and can be opened from the saved-plan list. Duplicate plan IDs are rejected instead of overwriting earlier files. A saved plan can be explicitly activated, switched, or cleared. Today shows the active plan's item for its local date, and the Plan destination provides a month calendar with selected-day details. Renaming the active plan, rescheduling one entry, adding one workout or rest entry, and removing one entry each produce a complete `schemaVersion: 2` snapshot with `revision.rootPlanId`, a sequence number, and the previous revision ID; the imported package and earlier snapshots remain unchanged. Each revision preserves workout definitions and all unaffected plan data, and may contain only the one name or schedule operation it represents. The final schedule entry cannot be removed. Schedule edits do not infer completion or modify workout definitions or history. Multiple workouts may share a date; a rest day may not share a date with any other item. The schema does not claim strength plan support yet. The original Relven v3 plan-package schema had an incompatible `enum: [1, 2]` and `const: 3` on `workoutSchemaVersion`; it was not copied as the new canonical plan schema.

The offline [AI Plan Kit](ai-plan-kit/README.md) packages the canonical plan v1, app-managed revision v2, workout v3, and exercise catalog v1 schemas with capability metadata, generation instructions, and running plus strength/prehab examples. AI output targets a new v1 plan; it must not invent v2 revision metadata.
