# Relven AI Plan Kit design

## Intent and constraints

Make Relven's supported running-plan format usable with external AI tools from the phone itself. Users can copy the plan-generation instructions, share the complete kit, or save the kit as a ZIP. The kit is generated from the schemas and example already implemented in this repository; Relven does not call an AI service.

Preserve application ID `se.hampusandersson.relven`. RunnerUp remains responsible for workout execution and history. Do not use the physical Android device until all product phases are complete and the app is ready for manual testing. Keep one PR open at a time and merge it before starting another.

## User behavior

- Add an `AI Plan Kit` action to the existing Workout Manager beside plan import and saved-plan access.
- The action offers three native operations: copy the generation instructions to the clipboard, share the full kit ZIP with Android's chooser, and save the full kit ZIP through Android's document picker.
- Show localized English and Swedish labels and feedback for successful copy/save and operation failures. The share path uses a cache-backed, non-exported FileProvider URI with read permission.
- The operation works offline and does not require a signed-in account, web app, network connection, or AI API key.

## Kit contents and support boundary

- Build a deterministic `relven-ai-plan-kit-v1.zip` from checked-in sources. Include a README, concise generation instructions, capability metadata, the canonical plan v1 and app-managed plan v2 schemas, the canonical workout v3 schema, and the supported running-plan example.
- New plans generated by AI target `schemaVersion: 1`. Schema v2 describes app-managed immutable revisions and requires a saved predecessor; the instructions must not ask an AI to invent revision metadata.
- Describe only the current importer subset: running, workout/rest days, supported v3 step/end/target forms, valid IANA timezone and dates, no duplicate IDs or rest/workout collisions, and the 4 MiB JSON limit. Strength, arbitrary exercise prescriptions, plan ZIP import, server sync, and plan-linked workout execution are not supported by this kit.
- Generate ZIP entries with stable ordering, timestamps, permissions, and normalized LF text so an unchanged source tree produces identical bytes. Check in the generated archive as the Android asset and provide a `--check` mode that fails when it is stale.

## Implementation shape

- Keep source instructions, capability metadata, and package README under `docs/ai-plan-kit/`.
- Build the archive with a Python standard-library script using the repository's existing schemas and example as inputs. Do not copy or edit the canonical schema files for the archive.
- Add a small Android helper that reads the bundled asset, extracts the instructions for clipboard copy, and streams the same ZIP to a destination or share-cache file.
- Use `ActivityResultContracts.CreateDocument` for saving and a cache-scoped AndroidX `FileProvider` for sharing. Keep the existing WorkoutFileProvider restricted to workout JSON files.
- Update the implementation status, feature parity, and README with the actual kit scope and generator command.

## Verification

- Python tests verify archive determinism, exact entry set, source-file parity, and capability flags. `--check` verifies the checked-in Android asset is current.
- Robolectric tests verify the bundled ZIP is readable, instructions can be copied out, and exported bytes match the bundle.
- Run the full local app debug/release build, app unit tests, lint, formatting, `git diff --check`, and schema/ZIP validation. Inspect Android chooser, clipboard, save, error, and localized paths from source/tests. Do not use the protected physical device.
- Obtain an independent code review, address actionable findings test-first, then open one PR and wait for hosted CI before merging.
